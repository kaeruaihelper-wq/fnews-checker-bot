# FNEWS — новости Yahoo Finance в Telegram

Автономный бот [@FNewsChecker_bot](https://t.me/FNewsChecker_bot) на **Telegram Serverless**.
Он находит свежие новости Yahoo Finance, переводит их на русский, определяет
затронутые акции и публикует **каждую новость отдельным постом** в канал
**Financial News**.

## Как выглядит публикация

- Одна новость — один пост. Никаких дайджестов из нескольких новостей.
- Заголовок и краткое содержание — **на русском** (машинный перевод). Если
  перевод недоступен, пост выходит с оригинальным английским текстом.
- Фото — обложка статьи Yahoo Finance. Если обложки нет, пост выходит **без
  фото**, заглушка не подставляется.
- В подписи: заголовок, краткое содержание (1–2 предложения из описания Yahoo)
  и тикеры (`$NVDA`, `$TSLA`).
- Публикуются только новости **текущего дня (МСК)** не старше 6 часов.
- Если свежих новостей нет, бот **ничего не публикует**.

## Возможности

- Проверка Yahoo Finance каждые 5 минут через внешний планировщик.
- Перевод заголовков и описаний на русский через Google Translate.
- Публикуются только новости текущего дня (МСК) не старше 6 часов — старый
  backlog не вываливается в канал после простоя.
- До 5 отдельных постов за один запуск (настраивается командой `/posts`).
  Лишние свежие новости переносятся на следующий запуск.
- Дедупликация по `uuid`/ссылке и нормализованному заголовку.
- Определение акций по `relatedTickers` и cashtag-ам в заголовке (`$NVDA`),
  отдельная пометка для новостей обо всём рынке (S&P 500, Dow Jones, Nasdaq).
- Автоматическая регистрация канала при добавлении бота администратором.
- Панель управления в личке владельца на русском: статус, пауза, интервал,
  максимум постов, список каналов.
- Команда `/news` в канале для внеочередной проверки.

## Почему внешний планировщик

В Telegram Serverless нет cron или таймеров — только обработчики обновлений и
endpoints для Mini App. Бот не получает собственные сообщения из канала, поэтому
самозапуск по посту невозможен. Планировщик лишь вызывает готовый модуль
`endpoints/tick`; вся логика остаётся на платформе.

## Первый запуск

```powershell
npm install
npx tgcloud login        # один раз: привязать папку к боту
npx tgcloud push         # задеплоить модули
npx tgcloud migrate      # создать/обновить таблицы БД
npx tgcloud webhook sync # привести webhook к обработчикам
```

`push` не применяет схему БД — после изменений в `tgcloud/schema.js` всегда
запускайте `migrate`. После изменения списка обработчиков полезно выполнить
`webhook sync`.

## Планировщик

### GitHub Actions (рекомендуется)

1. Создайте репозиторий на GitHub и отправьте туда проект.
2. В **Settings → Secrets and variables → Actions** добавьте секрет
   `TGCLOUD_TOKEN`.
   Это **CLI access token** из @BotFather (bot → Serverless → CLI Access),
   формат `app<id>:<secret>`. Это не токен Bot API.
3. Workflow `FNEWS tick` запускается по расписанию `*/5 * * * *`.
   Первый запуск можно сделать вручную: **Actions → FNEWS tick → Run workflow**.

GitHub может задерживать плановые запуски на несколько минут, а после 60 дней
без активности в репозитории расписание отключается — GitHub пришлёт письмо,
workflow нужно включить снова. Для новостного канала это допустимо: бот
проверит свежесть и опубликует только актуальные новости.

Для **приватного** репозитория запуск каждые 5 минут может превысить бесплатные
минуты GitHub Actions. Публичный репозиторий (секреты хранятся в настройках, не
в коде) или Windows Task Scheduler ниже — более экономные варианты.

### Windows Task Scheduler (запасной вариант)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-task.ps1
```

Скрипт создаёт задачу `FNEWS tick` с повтором каждые 5 минут. Задача работает,
пока пользователь Windows вошёл в систему, и использует сохранённые учётные
данные `.tgcloud/credentials`. Удалить задачу:

```powershell
Unregister-ScheduledTask -TaskName 'FNEWS tick' -Confirm:$false
```

### Ручной запуск

```powershell
npx tgcloud run endpoints/tick '{ compact: true }' --ctx '{ initData: { user: { id: 1709377874 } } }'
```

`--ctx` обязателен: endpoint проверяет, что вызывающий — владелец. Для
принудительной публикации вне интервала добавьте `force: true`:

```powershell
npx tgcloud run endpoints/tick '{ compact: true, force: true }' --ctx '{ initData: { user: { id: 1709377874 } } }'
```

## Команды бота

Команды в личке доступны только владельцу; `/start` и `/help` — всем.

| Команда | Действие |
|---------|----------|
| `/start` | Приветствие и кнопки |
| `/help` | Справка |
| `/news` | Проверить Yahoo Finance и опубликовать свежие новости |
| `/preview` | Показать готовые посты без публикации |
| `/status` | Состояние, каналы, статистика, последняя ошибка |
| `/pause`, `/resume` | Пауза и продолжение автопостинга |
| `/interval 5` | Интервал в минутах (5–1440) |
| `/posts 5` | Максимум постов за запуск (1–10); `/digest` — старый алиас |
| `/channels` | Список каналов |
| `/addchannel` | Инструкция по подключению канала |
| `/setchannel @name` | Подключить канал вручную |
| `/removechannel <id>` | Отключить канал |

В канале работает `/news` — бот удаляет команду и проверяет новости. Если
свежих новостей нет, в канале ничего не появляется.

## Настройки

Константы — в `tgcloud/lib/config.js`:

- `DEFAULT_MAX_POSTS = 5` — сколько отдельных постов максимум за запуск.
- `MAX_POST_AGE_HOURS = 6` — новости старше этого возраста не публикуются.
- `DAY_OFFSET_MINUTES = 180` — часовой пояс для «текущего дня» (МСК, UTC+3).
- `DEFAULT_INTERVAL_MINUTES = 5` — интервал проверки.
- Поисковые запросы, лимиты Yahoo и User-Agent — там же.

Заглушки для новостей без фото больше нет: такой пост публикуется текстом.
Перевод выполняет публичный endpoint Google Translate без ключа; при его
недоступности пост выходит на английском, а не пропускается.

Настройки, которые меняются командами, хранятся в таблице `settings`:
`enabled`, `intervalMinutes`, `maxItems` (максимум постов за запуск),
`lookbackHours`. Каналы — в `channels`; опубликованные новости — в `seen_news`
(чистятся старше 30 дней).

## Логика работы

1. Планировщик вызывает `endpoints/tick`.
2. Бот ищет новости в Yahoo Finance: общие запросы плюс trending-тикеры.
3. Отбрасывает уже опубликованное, новости старше 6 часов и новости не из
   текущего дня (МСК).
4. Берёт до `maxItems` самых свежих историй, загружает краткое описание,
   переводит заголовок и описание на русский и публикует каждую отдельным
   постом: с фото, если у новости есть обложка, иначе текстом.
5. Помечает доставленные новости просмотренными. Отложенные свежие новости
   останутся на следующий запуск; если свежих нет — тишина.

Короткий lock (2 минуты) не даёт двум запускам пересечься. Если публикация
не удалась во все каналы, новость не помечается просмотренной и будет
повторена при следующем запуске. При ошибке 403 канал автоматически
отключается — верните боту право «Публикация сообщений» и подключите канал
снова.

## Диагностика

| Симптом | Причина и решение |
|---------|-------------------|
| `skipped: interval` | С прошлого запуска прошло меньше интервала. Подождите или запустите с `force: true`. |
| `skipped: paused` | Автопостинг на паузе — `/resume`. |
| `skipped: locked` | Идёт другой запуск; lock живёт 2 минуты. |
| `posted: 0`, `fresh: 0` | Свежих новостей нет — это нормальное поведение, бот молчит. |
| `deferred: N` | Свежих новостей больше лимита; остальные уйдут следующим запуском. |
| `posted: 0`, `channels: 0` | Нет включённых каналов — `/channels`, `/setchannel`. |
| Ошибка 403 при публикации | Бот удалён из канала или потерял право «Публикация сообщений». Канал автоматически отключается. |
| Ошибки фото | Telegram не смог скачать обложку. Пост не отправлен и повторится при следующем запуске; проверьте `/status`. |
| В посте нет фото | У новости нет обложки Yahoo — так и задумано, пост публикуется текстом без заглушки. |
| В посте нет описания | Yahoo не отдал meta description статьи. Пост всё равно опубликован с заголовком и тикерами. |
| Пост на английском | Google Translate временно недоступен. Новость опубликована с оригинальным текстом, перевод появится в следующих постах. |
| В `/status` ошибка Yahoo | Yahoo временно недоступен или изменил API. Повторится на следующем запуске. |
| Нет автопубликации | Не настроен планировщик. Проверьте Actions или задачу Windows; ручной `/news` работает всегда. |
| `No CLI access token` | Выполните `npx tgcloud login` или задайте `TGCLOUD_TOKEN` (для CI). |

## Безопасность

- `.tgcloud/` содержит access token и исключён из git через `.gitignore`.
  Не коммитьте его и не публикуйте.
- CLI access token (`app…`) и Bot API token (`<id>:AA…`) — разные секреты.
  В GitHub Actions нужен первый.
- Бот должен быть администратором канала с правом «Публикация сообщений».
  Для удаления команды `/news` желательно также право «Удаление сообщений».
